## 지금 어떻게 돌고 있나 (한눈에)

```
교사 휴대폰/PC
      │  https://suwon-es.tailf616c8.ts.net
      ▼
 Tailscale Funnel (외부 공개 터널)
      │
      ▼
 [ NAS 안의 Docker 컨테이너 4개 ]
   frontend(nginx) ──/api──▶ backend ──▶ mariadb
   tailscale ── 위 frontend 로 프록시
```

- **접속 주소**: `https://suwon-es.tailf616c8.ts.net`
  - 인터넷 어디서든 접속됩니다(집·휴대폰 포함). 인증서 자동이라 경고가 뜨지 않습니다.
  - 교회 내부망에서는 `http://<NAS_IP>:8080` 으로도 접속됩니다.
- **왜 이 방식인가**: 이 망은 공유기가 3겹(다중 NAT)이라 포트포워딩이 불가능하고,
  공유기 관리자 계정도 확보하지 못했습니다. 그래서 NAS 가 밖으로 나가 연결을 유지하는
  터널(Tailscale Funnel)로 공개합니다. QuickConnect 와 같은 원리입니다.
  (QuickConnect 는 DSM·Synology 패키지만 중계해서 이 앱에는 쓸 수 없습니다)

## 무엇으로 이루어져 있나

| 구성요소 | 설명 | 위치 |
|---|---|---|
| 소스코드 | 프론트(Vue) + 백엔드(Express) + 배포설정 | GitHub 저장소 `SangwookJeong/suwon_es_admin` |
| 자동 배포 | main 에 push → 이미지 빌드 → NAS 자동 갱신 | `.github/workflows/deploy.yml` |
| NAS 실행 | Docker 컨테이너 4개 | `deploy/docker-compose.nas.yml` |
| 데이터 | MariaDB (학생·교사·출석·계정) | NAS 의 `mariadb_data` 볼륨 |
| 외부 공개 | Tailscale Funnel | `tailscale` 컨테이너 + Tailscale 계정 |

**소유권이 걸린 계정 4가지** (전부 정상욱에게 문의):

1. **GitHub 계정** — 소스코드와 자동 배포. 저장소 `SangwookJeong/suwon_es_admin`
2. **GitHub PAT 토큰** — NAS 러너가 GitHub 에 붙는 열쇠. GitHub Secrets 의 배포용 비밀값들
3. **Tailscale 계정** — 외부 공개 주소(`*.ts.net`)의 소유권. 이 계정을 잃으면 접속 주소가 끊깁니다
4. **NAS 관리자 계정** — DSM 로그인 및 SSH 접속

> ⚠️ 담당자가 바뀔 때는 위 4가지 로그인 정보를 반드시 인계받으세요.
> 특히 Tailscale 계정을 잃으면 외부 접속 주소가 사라집니다.

## 자주 하는 작업

명령은 NAS 에 SSH 로 접속(관리자 계정)한 뒤 실행합니다.
`docker` 명령이 권한 오류(`permission denied`)를 내면 먼저 `sudo -i` 로 root 가 되세요.

```bash
C="docker compose -f deploy/docker-compose.nas.yml"   # compose 없으면 docker-compose
```

### 상태 확인

```bash
docker ps --filter name=suwon-es --format "table {{.Names}}\t{{.Status}}"
```

컨테이너 4개(mariadb / backend / frontend / tailscale)가 보이면 정상입니다.

### 외부 공개 주소 확인

```bash
docker exec suwon-es-tailscale-1 tailscale funnel status
```

`https://suwon-es.<...>.ts.net (Funnel on)` 이 보이면 정상입니다.

### 로그 보기 (문제 생겼을 때)

```bash
docker logs --tail 50 suwon-es-backend-1
docker logs --tail 50 suwon-es-frontend-1
```

### 코드 수정 후 배포

개발 PC 에서 코드를 고치고 `git push origin main` 하면 자동으로 배포됩니다.
GitHub 저장소의 **Actions** 탭에서 진행 상황을 볼 수 있습니다.

### 데이터 백업 (중요)

영속 데이터는 `mariadb_data` 볼륨 하나뿐입니다. 이것만 백업하면 됩니다.
DB 비밀번호는 컨테이너 환경변수(`MYSQL_ROOT_PASSWORD`)에 들어 있어 아래 명령이 자동으로 씁니다.

```bash
docker exec suwon-es-mariadb-1 \
  sh -c 'exec mariadb-dump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines suwon_es_admin' \
  > /volume1/backup/suwon_es_$(date +%Y%m%d).sql
```

DSM **작업 스케줄러**에 매일 새벽으로 걸어두길 권합니다.

### 복구

```bash
docker exec -i suwon-es-mariadb-1 \
  sh -c 'exec mariadb -uroot -p"$MYSQL_ROOT_PASSWORD" suwon_es_admin' \
  < /volume1/backup/suwon_es_YYYYMMDD.sql
```

## 문제가 생기면

| 증상 | 확인/조치 |
|---|---|
| 외부에서 접속 안 됨 | `docker exec suwon-es-tailscale-1 tailscale funnel status` — `Funnel on` 인지 확인 |
| 터널이 `Logged out` | Tailscale 인증키 만료. 정상욱에게 문의해 새 키 발급 후 재배포 |
| 배포가 `Waiting for a runner` 에서 멈춤 | NAS 러너가 죽음. `docker restart nas-runner` 후 `docker logs nas-runner` 에 `Listening for Jobs` 확인 |
| 화면은 뜨는데 로그인 500 | `docker logs suwon-es-backend-1` — 보통 DB 연결 문제 |
| 화면이 옛날 그대로 | 브라우저 하드 리프레시(⌘⇧R 또는 Ctrl+F5) |

더 자세한 배포 절차는 [NAS-배포.md](./NAS-배포.md) 를 보세요.
